# VISUAL LANGUAGE v1.0

Status: DRAFT
Date: 2026-09-04
Truth level: PROVISIONAL

## Purpose

This document defines the recognizable CAPICAPI visual language. It protects the IP from becoming a disconnected set of generic capybara prints.

## Brand Feel

CAPICAPI should feel:

- calm
- collectible
- warm
- clever
- tactile
- characterful without being over-detailed
- designed for physical manufacture

CAPICAPI should not feel:

- generic
- hyper-realistic
- randomly cute without structure
- fragile
- paint-dependent
- like unrelated models from different artists

## Shape Grammar

Use:

- rounded primary forms
- broad readable planes
- low relief detail
- fused accessories
- thickened silhouettes
- intentional chamfers
- simplified expressions

Avoid:

- needle-thin parts
- hairline grooves
- realistic fur
- unsupported floating details
- unrelated art styles between variants
- excessive micro-accessories

## Core Recognition Signals

Every Capi should carry:

- rounded capybara head/body language
- simple calm face
- sturdy low stance
- small integrated ears
- broad muzzle
- accessory or costume language secondary to the base character

## Color Philosophy

Color communicates identity but must serve manufacturing.

Rules:

- maximum 4 automatic colors per standard Capi
- target 3 colors when possible
- no fifth color just because the real-world reference has it
- use geometry for stitching, buttons, chains, zippers, badges, and seams where possible
- avoid color regions that create excessive Z-layer swaps unless justified

## Detail Language

Preferred detail types:

- embossed lines
- recessed lines
- raised icons
- thickened straps
- relief seams
- integrated clothing panels

Details must be validated through Capi v0 tests before becoming master rules.

## Character Families

Initial possible character families:

- professions
- adventure roles
- fantasy roles
- seasonal variants
- material/shiny variants
- limited edition colorways

No family is approved for Series 01 yet.

## Consistency Checklist

A candidate variant must answer yes to all:

- Does it read as the same Capi base character?
- Does the accessory support the role without dominating the body?
- Does the silhouette remain simple?
- Are details printable with a 0.4 mm nozzle after validation?
- Does the color plan respect AMS Lite constraints?
- Would the character still be recognizable without marketing text?

## Visual IP Risks

- Over-customized variants may dilute the core Capi identity.
- Accessory-first concepts may hide the base character.
- AI-generated references may drift unless checked against this document.
- Physical print constraints may force simplification of the visual language.
